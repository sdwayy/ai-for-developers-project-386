# Генерация API-артефактов: TypeSpec → OpenAPI → openapi-ts, с коммитом вывода

Источник правды — TypeSpec: `spec/*.tsp` компилируется в `spec/openapi.json` (**OpenAPI 3.0.0**, дефолт эмиттера), а из него `@hey-api/openapi-ts` генерирует клиентский SDK и серверные схемы в `src/shared/api/generated/`. Компилятор официальный и GA — `@typespec/compiler`, `@typespec/http`, `@typespec/openapi3` (1.17.x); генератор — `@hey-api/openapi-ts` (0.99.x) с плагинами `@hey-api/typescript` (только типы, в бандл не попадают), `@hey-api/sdk` (клиент) и `zod` (**Zod v4**). Генерируются схемы запросов и определений, схемы ответов выключены. HTTP-клиент — Fetch API, а не Next.js-плагин: через клиент ходят только записи из клиентских компонентов, серверный кэш Next не задействован (ADR-0004). Вся цепочка — чистый Node, поэтому JDK не нужен ни локально, ни в CI.

Всё сгенерированное коммитится: и `src/shared/api/generated/` (`types.gen.ts`, `sdk.gen.ts`, `zod.gen.ts`, `client.gen.ts`, `client/`, `core/`, `index.ts`), и `spec/openapi.json`. Так `yarn build` работает без шага генерации, диффы ревьюируемы, а проверка идемпотентности осмысленна. Заготовки маршрутов не генерируются — ни один генератор не эмитит Next.js App Router `route.ts`; `app/api/**/route.ts` пишутся руками и остаются тонкими. Серверные типы берутся как `import type` из `generated/types.gen.ts` (рантайм клиента в серверный бандл не протекает), серверная валидация в Route Handlers — zod-схемами из `generated/zod.gen.ts`; решения #7 и #8 остаются в силе без правок.

Воспроизведение — одна команда: Make делегирует в `package.json` (версии и шаги в одном месте, работает через corepack) — `make api` → `yarn api:generate` (компиляция спеки + генерация), `make api-check` → `yarn api:check` (генерация + `git diff --exit-code` на `src/shared/api/generated` и `spec/openapi.json`). Тулчейн пинится точными версиями без `^`; `zod` v4 — рантайм-зависимость. В `.github/workflows/ci.yml` добавляется шаг `make api-check`, в `tspconfig.yaml` — `warn-as-error: true`; `.github/workflows/hexlet-check.yml` не трогаем.

**Considered Options**: официальные клиентские эмиттеры TypeSpec (`@typespec/http-client-js`, preview 0.16.3) — отклонено: zod не дают (серверная валидация потребовала бы JSON Schema + Ajv вместо zod), а preview-статус не даёт выигрыша в стабильности перед `openapi-ts`; `openapi-generator` и Java-эмиттеры (`autorest.java`, `@typespec/http-client-java`) — отклонено: требуют JDK локально и в CI; `orval` и `openapi-typescript` + рукописный zod — отклонены в пользу одного генератора, который отдаёт типы, нейтральный Fetch-клиент и zod-схемы из скомпилированной спеки одной командой.

**Consequences**: более ранние ответы по инструментам заменены — вариант с официальными эмиттерами TypeSpec и JSON Schema + Ajv снят в пользу `openapi-ts` с zod. Артефакты коммитятся, поэтому выбор трудно обратим: смена генератора переписывает весь diff `src/shared/api/generated/`. Пайплайн дополняет ADR-0004 (чтения in-process из серверного data-модуля, записи через сгенерированный клиент за фасадом) и не отменяет его.
